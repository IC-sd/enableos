# EnableOS Web

[![Validate](https://github.com/IC-sd/enableos/actions/workflows/ci.yml/badge.svg)](https://github.com/IC-sd/enableos/actions/workflows/ci.yml)

EnableOS 是一个浏览器优先、本地优先的 AI 赋能工作底稿。它不预设你入职后一定会做知识库、Agent 或自动化，而是让任何工作沿着一条连续路径推进：

> 收到要求 → 澄清目标 → 组织证据 → 验证方案 → 交付与复盘

日常使用只需打开浏览器。任务、资料、实验和交付默认保存在当前浏览器的 IndexedDB；没有网络时仍可打开已缓存的页面并使用本地能力。

## 已完成能力

- 工作线：从一条真实原始要求出发，按“原始要求 → 澄清 → 行动 → 证据 → 交付”推进；顶部同步显示回答、步骤、依据和交付进度。完成操作需要确认，误点后可直接“重新打开”，完成时间同步清除且保留活动记录。
- 今天：按逾期、今天、未来 7 天、未排期和更晚自动分组；可直接改到今天/明天/+7 天、开始、完成或重新打开，日期与状态变更都会留下快照。
- 任务流：保留领导/导师原话，可完整编辑标题、当前理解、优先级、日期、来源、已有项目、澄清答案、步骤进度、交付物和验收标准。
- 工作空间：把较大的任务升级成项目，完整维护名称、目标、背景边界、部门、日期、状态、标签、交付、风险和下一步；项目、资料、试验和交付是工作线的派生视图。
- 证据库：浏览器内批量导入并统一归类 PDF、DOCX、XLSX、TXT、Markdown、CSV、JSON 和日志；保存原文件名、大小、修改时间和 SHA-256，可重新选择原文件核验；支持标签编辑、引用检索和语义混合检索。
- AI 实验：完整编辑场景、评分、风险、输入输出、原型计划和成功指标；建立固定测试集，保存每次模型/提示词版本、得分、通过率和失败说明，再记录采用/迭代/停止决定。
- 交付中心：可命名、更新、另存和删除交付版本；按全部工作、项目或具体工作线生成汇报，最小证据包持续校验 `[T1]`、`[A1]`、`[P1]`、`[S1]`、`[K1]` 引用。
- 恢复与历史：任务、项目、资料、场景和交付统一软删除到回收站；可恢复或二次确认永久删除。显式修改前自动保存快照，并可恢复旧版本。
- 本地优先：按实体增量写入 IndexedDB、写前恢复日志、申请浏览器长期存储、单写标签页保护与跨标签同步；PBKDF2 + AES-GCM 加密备份改为遮罩密码对话框。
- PWA：生产版带 Service Worker，可离线打开；也可选择浏览器的“安装应用”，但不是必须。
- 精确地址与搜索：任务、项目、资料、实验和汇报都有可刷新实体地址；全局搜索直接打开具体记录，不只跳到模块首页。
- 入职边界核对：记录公司允许的平台、资料外发/脱敏规则、导师首月预期和汇报节奏；未明确允许时不会上传资料。默认仅允许公开证据，内部资料必须再次明确选择，敏感资料始终排除。
- 安全模型网关：支持 Responses API 和 Chat Completions，提供生成与向量双诊断；会话密钥绑定保存时的端点。请求发出前会阻止可能的密钥、密码、私钥、身份证号和手机号误外发。
- 数据审计：可导出并重新验证逐事件 SHA-256 哈希链；活动保留上限为 5,000 条。
- 数据健康：检测和安全修复失效项目/工作线关联、异常评分与颠倒日期；重复标识和重复证据只提示，不自动删除。
- 导入安全：PDF保留页码，内容指纹防止重复导入；DOCX 在解压前预检目录和膨胀大小；备份与审计导入设有体积和加密参数上限。

## 日常打开

首次准备可以直接双击 `首次安装 EnableOS.cmd`。它会使用锁定的 pnpm 版本安装依赖、运行类型检查和测试，并生成生产版本。也可以手动执行：

```powershell
pnpm install
pnpm build
```

之后可以直接双击 `启动 EnableOS.cmd`。它会启动仅监听本机的网页服务，并自动用默认浏览器打开：

```text
http://127.0.0.1:4173
```

不用时可双击 `停止 EnableOS.cmd` 安全关闭本机服务。刷新页面和浏览器前进/后退会保留当前模块地址。

也可以在终端运行：

```powershell
pnpm serve
```

遇到“缺少构建”“端口占用”或新电脑环境不确定时运行：

```powershell
pnpm run health
```

## 换电脑与数据迁移

GitHub 仓库只保存程序代码，不会包含浏览器 IndexedDB 中的任务、资料、实验和交付。完整迁移需要同时移动代码和加密备份：

1. 在旧电脑进入“设置 → 数据、备份与审计”，导出加密备份并妥善保存密码。
2. 在新电脑克隆本仓库，并安装 Node.js 20 或更高版本。
3. 双击 `首次安装 EnableOS.cmd`，完成后再双击 `启动 EnableOS.cmd`。
4. 在新电脑的设置页导入 `.enableos` 备份，确认任务和资料数量后再继续工作。

设置页会记录最近一次成功备份时间；超过 14 天或从未备份时会提醒。换电脑、浏览器重装和重要交付前都建议重新导出。

## 开发与验证

```powershell
pnpm dev
pnpm typecheck
pnpm test
pnpm build
pnpm run health
```

浏览器烟雾测试还需要提供 Playwright 包目录，例如在 Codex 工作区中设置 `PLAYWRIGHT_PATH` 后运行 `pnpm test:browser`；日常使用无需安装 Playwright。

- 开发页面：`http://127.0.0.1:5173`
- 开发 AI 网关：`http://127.0.0.1:8787`
- 生产页面与网关：`http://127.0.0.1:4173`

## 配置模型

默认“本地方法”无需模型和密钥。需要模型增强时有两种方式：

1. 在设置页输入本次会话密钥。密钥只留在本机网关内存，关闭服务即清除。
2. 启动前设置环境变量，适合固定个人环境：

```powershell
$env:ENABLEOS_API_KEY='你的密钥'
$env:ENABLEOS_API_ENDPOINT='https://api.example.com/v1'
$env:ENABLEOS_API_MODEL='模型名称'
pnpm serve
```

设置页可选择 Responses API（OpenAI 默认推荐）或 Chat Completions 兼容协议。语义混合检索需再填写服务支持的向量模型；片段向量只缓存在浏览器本地。必须先在“入职边界核对”中明确公司允许外部 AI，系统才会发送非敏感资料。

## 项目结构

```text
src/                 浏览器前端、IndexedDB、文件解析与本地规则
server/              同源本机 AI 网关和静态网页服务
shared/              数据模型与接口
scripts/             浏览器自动验收
docs/                架构说明和验收截图
.github/workflows/   GitHub 自动类型检查、测试、构建与运行布局验证
```

`private: true` 仅用于阻止误发布到 npm；仓库本身仍是公开的。当前未附开源许可证，代码公开可见不等于授予复制、分发或商用许可。

完整的产品边界、研究依据和前后端设计见 [产品与架构说明](docs/PRODUCT-ARCHITECTURE.md)。
